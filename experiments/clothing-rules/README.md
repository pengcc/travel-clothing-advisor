# 德国旅行穿衣建议（命令行实验）

此目录包含**候选规则演示**，不是已发布的旅行服务。德国城市天气来源为 Open-Meteo，使用德国当地时间；没有网页或自动更新服务。

## 只查看旅行期间的天气

```bash
# 例如 2026 年 10 月 17–20 日去柏林
python3 experiments/clothing-rules/forecast_advice.py --start 2026-10-17 --end 2026-10-20

# 比较怕冷时
python3 experiments/clothing-rules/forecast_advice.py --start 2026-10-17 --end 2026-10-20 --preference cold

# 查看所选日期的逐日计算依据
python3 experiments/clothing-rules/forecast_advice.py --start 2026-10-17 --end 2026-10-20 --details

# 不提供 --start / --end 时，保留原先的未来14个日历日演示
python3 experiments/clothing-rules/forecast_advice.py
```

`--start` 与 `--end` 必须同时提供，含首尾日期。仅接受**本次获取的从今天开始14个日历日**内完整覆盖的旅行，不会悄悄忽略出行日期或用无关日期代替。若已经过了今天白天，今天不再贡献白天气温；行程只有今天且白天已过时，程序明确报错。

**选择日期后重新计算**整趟行程的典型白天气温、主要厚度、偏冷日期和风雨雪提醒，而不是将整个14天的建议简单裁掉一段文案。预报第8～14天的不确定性始终按**真实预报提前量**判断：即使旅行从预报第10天开始，它仍是远期预测。

## 提前15～30天：同期历史范围（新实验）

```bash
python3 experiments/clothing-rules/trip_advisor.py --city Berlin --start 2026-11-08 --end 2026-11-12
python3 experiments/clothing-rules/trip_advisor.py --city München --start 2026-11-08 --end 2026-11-12 --preference cold
```

以上日期是示例：请按实际运行日期调整。**同一个 `trip_advisor.py` 命令**在整趟旅行处于未来14个日历日时使用真正的天气预报，并附两年历史参考；只要行程有一天超过预报覆盖范围，但仍完全处于未来30个日历日内，则**整趟改用历史天气参考**，不拼接一半预报一半历史估计。超过30天明确报错。

远期采用最近8个对应年份、固定 **ERA5** 历史再分析模型，计算历史**白天代表温度**（09:00–18:00）及**早晚代表温度**（06:00–08:00、19:00–22:00）。默认只输出**最重要的衣物厚度结论＋可穿脱搭配**，并在天气信号可能改变准备决定时明确增加提醒：历史早晚通常低于10°C，或比白天低至少5°C时提醒加减衣物；8年中至少2年同期出现明显降水时提示雨具；任一年出现历史降雪记录时提示临近出发核对雪预报及鞋底防滑。**这些是候选文案触发阈值，非经验证的个体舒适度或降水概率。** --details 保留温度区间、极冷样本、历史降水与降雪年份计数及逐年明细。个别历史年份的最低白天代表温度／最低早晚采样值**不是**未来最低温预报，也**不是**某一天的实测全天最低温；天气模型的时间戳与日照时间、夏令时转换仍有近似边界。**不预测具体日期的气温或降雨，不计算漏带衣服的概率，也不声称可以安全省略某件具体衣物。** 天气临近时需重新运行；没有后台自动更新或实测准确率证据。远期模式会发起8次历史天气查询；任一年白天或早晚窗口数据不完整或API请求失败，则报错而非编造数据。短期模式的历史两年参考不新增早晚数据完整性要求。

**2026-10-15 首次长期路径实际试用：** 用户提供 Berlin 2026-11-08～12 的成功输出（白天同期年份代表温度范围 4.2～12.4°C，中位 7.7°C；个别历史年份最凉白天代表值 0.6°C；8年中有3年在对应行程出现较明显降水）。这说明长期 API 查询与输出路径至少曾在真实环境中运行成功，但未保留原始 Open-Meteo JSON，因此**不能独立核验这组历史数字**，也不说明新版本的早晚统计已经完成联网验证。

## 离线验证

```bash
python3 -m unittest discover -s experiments/clothing-rules -p 'test_*.py' -v
```

离线测试包含原有 `test_trip_dates.py` 等测试，并增加 `test_monthly_outlook.py` 检查长短期路径切换、ERA5 URL、跨年与闰年、历史早晚小时窗口、缺失数据、优先衣物结论，以及早晚低温／雨雪提醒的**触发与不触发**。测试不访问网络，也不验证实际气象资料或衣物体感适配性。

## 2026-10-15 实际出行日期试用反馈

用户在柏林本地于 2026-10-15 11:25 运行了 2026-10-17～20 日的真实在线查询，命令成功输出旅行日期及**白天代表气温约12.9°C**。原版建议把 12.9°C 直接映射 L5，并显示“保暖外套或轻羽绒”，暴露了靠近 13°C 分档边界时语气偏重的问题。这是**真实联网输入后的输出反馈**，但原始接口 JSON 和四天逐日天气数值没有留存，不能当成完整天气数据验证。

现已在本 PR 中仅对**接近13°C（±0.75°C）**的默认穿衣文案使用相同的可拆分组合：长袖＋毛衣或抓绒＋适中外套；轻羽绒是怕冷或长时间早晚在外的可替换选项。对满足日间最低预报不低于9°C、早晚采样值不低于0°C且无降雪信号的行程，可温和提示不用优先带**厚冬季羽绒服**。真正更冷的旅行日期或突发极低温日仍保留保暖外套、冬装提示；不更改现有六级判断。新增 12.9/13.1°C 和极冷日的合成数据测试，但这些测试不等于新一轮实时 API 结果。

现有 `forecast_advice.py` 保留柏林14天演示；新增的 `trip_advisor.py` 支持德国城市和30天内的完整行程，其中远期仅为历史参考，不是15～30天预报。Open-Meteo免费接口为非商业用途；商业发布前需重新检查条款和署名要求。

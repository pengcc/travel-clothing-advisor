## 3. 关键交互不可改

- **按行程查询**：用户选德国城市、到达/离开日期、怕冷/一般/怕热，进入**行程穿衣建议**；结果只使用该入口参数。返回后保留表单。
- **精选城市**：独立点击，直接看德国当地「今天至+13天（含今天）」的**城市穿衣参考**，体感固定为一般。不能预填、读取或修改上面的行程表单。两个入口可以复用视图组件，不共享查询状态；分享参数不同。
- **首要答案**：具体回答外套带多厚、可选内搭，而不是气象数据堆叠。
- **温差的例外日**：哪怕 3 天行程 L2→L4→L2 或反向，只有一天需要不同衣服也应出现有意义的提醒。后端返回 `packing_variation_notice: string | null`，在完整结果的**外套结论紧下方**优先显示；首页精选城市卡片使用独立的短句 `packing_variation_summary: string | null`，不从长句截断。
- **标记**：临时信号格＋可读中文短标签，无独立“五档视觉对照”板块。未来更换为有识别度的动物形象，只改 `WarmthIndicator` 展示组件。主档位 `warmth_indicator_level: 1..6 | null` 与温差提醒**彼此独立**；没有代表性主档可显示文字「冷热变化大」，不能硬编主档。
- **远期与数据时间**：超出 14 天预报覆盖的整段行程使用历史同期参考，明确不是日期天气预报。德国当地时间与数据有效范围要核验；已过去的当天时段不应作为未来预测。来源与获取时间需真实。

## 4. 视觉落地边界

- 奶油白页面 `#FFF9F4`、白卡 `#FFFFFF`、正文 `#3D302A`、深陶土橙按钮 `#A64E35`、浅沙分隔 `#EADFD5`；完整颜色和无障碍对比度以 UI 规格为准。
- 手机优先，优先比较 320 / 375 / 390 / 430px，桌面约 1280px。
- 页面主要任务不是画精美图，而是**让用户第一眼看到需要带什么外套，发生大温差时马上注意到特别的一天**。
- 主状态保持简单：气温正常时不要制造提醒；变化有影响时使用一块浅色的简短提示，不用红色警报、弹窗或逐日穿搭清单。
- 原型可能仍有一些 fixture 简写（如历史行程示例、五档示意），如与 PR #16 规格不同，以最新规格为准。**切勿当成已上线功能或准确计算程序。**

## 5. 推荐交付顺序与验证

1. 让 Codex 对照 HTML 原型、截图及最新规格实现响应式**页面与交互**，先用明确标注的 fixtures 验证两个互不影响的查询路径和显示条件；开 PR 并附实际浏览器截图做视觉比对。
2. 按功能规格接入现有 Python 模型，适配实际天气/历史数据、缓存、API 与错误状态；在独立审查中验证前述跨日和冷热异常场景，而不是复制原型硬编码的 mock 逻辑。
3. 针对手机窄屏、跳转/返回、分享链接、德国当地跨日、数据来源、无障碍与故障状态做检查。未经批准不合并、部署生产或新增品牌动物形象。

**特别提醒**：本交接包用于传达视觉与交互。把它上传到 Codex 可读取的仓库目录（例如 `design/reference/v5/`）或作为 Codex 任务附件；只有当前 ChatGPT 会话里的 sandbox 下载链接，Codex 在另一个执行环境里未必能访问。

## Cost and failure interpretation

Each request consults current SQL state. No in-memory pointer conceals a DB outage. Cold `/api/featured` reads one immutable manifest plus ten sources; cold single-city advice reads one manifest plus one source; city search/resolve checks one manifest and uses local approved metadata without weather/geocoding. The UI paginates an already retrieved ten-city response without new weather IO. No process-wide Blob byte cache is claimed; repeated API requests currently repeat these reads. Measure actual SDK operations/bytes/latency and traffic at G1, and stop if the approved operation allowance is insufficient. Do not apply one-city S2 costs to this path.

Each healthy worker cycle seeds missing current-day jobs, refreshes heartbeat and tries at most ten cities serially within a 120-second work window, with four-second provider request bounds and a five-minute Action timeout. Claims have 150-second leases and generation fencing. Fewer-attempt cities get priority; cooldowns survive worker exit. Private immutable objects are read back before fenced city commits; only all ten current-day sources can yield a SQL publication. Website advice is get-only, not a download trigger. Healthy accepted work before noon may say preparing; missing heartbeat over three hours says scheduler unavailable; quota exhaustion says quota limited; incomplete after noon is unavailable and causes a failed Action checkpoint. A prolonged Actions outage has no independent alert source; no hourly hard SLA is promised.

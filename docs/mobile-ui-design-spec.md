# Travel Clothing Advisor — Mobile UI Design Specification (V1)

> **状态：** UI 设计候选稿，等待 Review；非实现或上线说明 · 2026-10-15  
> **上游功能规格：** [MVP Functional & Technical Specification](mvp-functional-technical-spec.md)（PR #15 已合并）。功能及数据规则以上游规格为准，本文件只定义视觉、页面布局与交互。  
> **已确认的设计选择：** Mobile-first；首页**查询优先**、结果页**穿衣结论优先**；**C · 轻快友好**配色（奶油白 / 陶土橙 / 浅沙色），不再比较蓝/绿主题。

## 1. 信息层级和页面

网站 V1 只有两个主要页面状态：

1. **首页 / 查询**：站点标识 → 主标题「去德国，带什么衣服？」与一句说明 → 城市 + 行程日期 + 体感的紧凑表单 → 主要操作「查看穿衣建议」 →「德国精选城市」摘要卡片与浏览入口。
2. **建议结果**：返回修改 → 城市、行程日期与体感 → 清晰标注「14 天内气温预报」或「过去 8 年同期气温参考」 → **外套厚度结论（页面最醒目）** → 内搭与可穿脱层 → 最多展示当前相关的气温/早晚提醒 → 依据与不确定性 → 分享/复制 → Open-Meteo 署名及数据时间。

**不要添加**：天气仪表盘、逐小时气温图、轮播大图、导航抽屉、多个重复 CTA、用户账户、时尚穿搭插画。即使手机一屏看不完所有城市，也应先让用户找到查询入口。

## 2. 配色：C · 轻快友好

| Token | 色值 | V1 用途 |
| --- | --- | --- |
| `--color-page` | `#FFF9F4` | 奶油白背景 |
| `--color-surface` | `#FFFFFF` | 表单 / 城市 / 结果卡片 |
| `--color-ink` | `#3D302A` | 标题、正文 |
| `--color-muted` | `#74665E` | 次要文字、说明 |
| `--color-brand` | `#C96849` | 陶土橙：图标、装饰和少量强调，**不配白色小字** |
| `--color-action` | `#A64E35` | 主按钮、文字链接、键盘焦点强调 |
| `--color-selected` | `#F4DBCF` | 单选已选背景、轻提示 |
| `--color-sand` | `#E8D6B9` | 浅沙色，谨慎用于低权重背景 |
| `--color-line` | `#EADFD5` | 卡片和表单边框 |

**对比度检查（设计计算值，待页面浏览器验证）**：白字 / 主按钮 `#A64E35` ≈ **5.58:1**；正文 / 奶油白 ≈ **12.15:1**；次要文字 / 奶油白 ≈ **5.29:1**。`#C96849` 上白字仅约 **3.78:1**，不能作为普通字号按钮文本配色。不要单靠颜色传达“选中、错误或数据过期”。

## 3. 排版、间距和响应式

- **中文优先**：采用系统无衬线字体栈（如 `-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`）；不依赖必须远程下载的中文字体。
- **文字等级**：手机 H1 30px / 1.25，结果结论 24px / 1.35，区块标题 20px / 1.35，正文 16px / 1.55，字段名 14px / 1.4，来源说明 13px / 1.5；遇到用户系统字体放大时允许换行、不裁切主要结论。
- **留白节奏**：4/8/12/16/24/32px；手机页面两侧留 16px；卡片内部 16px；区块间 24–32px。不要为了让首页恰好一屏装完而压缩文字。
- **控件**：输入与主要点击目标高度至少 44px，文本输入至少 16px 字体，焦点可见；卡片与主要按钮圆角 12–16px，输入框 12px。用细边框和留白而不是大量阴影建立层级。
- **响应式**：优先在 320/375/390/430px 手机宽度审查。手机表单一列；起止日期可并排两个显示字段，但若发生截断则改为整行日期区间入口。城市摘要在常见手机宽度可两列，窄屏或长文本允许一列。桌面保持同一信息架构，主内容限宽约 1040px，表单不应拉成整页宽。

## 4. 首页交互

- **城市输入**：优先搜索建议而不是自由经纬度。已选城市以明确标签显示；精选城市提供常见中文别名，其他德国城市按后端可支持的名称匹配；**不要默认承诺全部中文地名都可识别**。同名地点显示联邦州，要求选择明确结果；无匹配时提示尝试德文名。
- **日期区间**：两个可见字段「到达日期」「离开日期」；点击进入适合手机的日历选择流程，先开始再结束。德国当地今天至今天 +29 天可选，区间结束日不得早于开始日。非法或缺失值在字段附近展示清楚的纠正提示，不默默调整用户日期。
- **体感**：单组选项「怕冷 / 一般 / 怕热」；默认「一般」；可用键盘选中，状态同时有边框和文字，不仅靠浅橙底色。
- **提交**：单个显著的「查看穿衣建议」按钮；等待时展示「正在计算建议…」并防止重复提交，错误时保持表单值及重试入口。
- **精选城市**：首屏查询之后显示「德国精选城市 · 明日起 7 日」；从预取快照读取 10 城简短摘要（城市、外套结论、最多一条主要提醒）；浏览/分页方式由组件实现选择，但必须有文字/按钮可操作而非只靠滑动。点击卡片将城市填入查询表单，**不把统一 7 日参考冒充用户自己的旅行日期**；仍要求用户选择行程日期后提交。
- 首页不显示大型天气图、实时天气角标、没有数据依据的图标或图片；首版可以完全不使用城市照片。

## 5. 穿衣结果交互与内容

**预报模式（结束日在德国当地今天 +13 天内）**：显示日期、体感和「14 天内气温预报」。第一块醒目卡片给出具体外套厚度与内搭；只显示影响衣物选择的早晚偏冷/明显冷暖变化。气温作为解释而非主标题；远期预报要提示出发前复查。

**历史参考模式（旅行仍在未来 30 天内，但超出 14 天预报窗）**：相同卡片结构，但标识为「过去 8 年同期气温参考」，不展示未来某一天必然下雨/降雪/气温的文案；明确「这是提前备衣参考，不是该日期天气预报」，引导临近出发再查。

- **修改**：提供明显的「修改行程」返回操作，保留城市、日期和体感；不要清空用户已选内容。
- **复制/分享**：分享含城市 ID、日期及体感的可重算链接；复制简明建议时包含地点、日期、模式、数据时间及温度不确定性说明，避免旧文字脱离上下文。
- **信息结构**：结果最重要的句子优先，不将内部 L1–L6 直接暴露；数据来源（Open-Meteo）及 `weather_fetched_at` 必须实际可见。不要将缓存再计算时刻作为天气更新时刻。

## 6. 必须有的页面状态（不新增页面）

| 状态 | 表现 |
| --- | --- |
| 首页快照加载中 | 精选城市局部骨架屏/占位；表单仍可使用 |
| 首页快照不存在 | 精选城市明确显示「参考暂未准备好」，表单继续可用 |
| 数据过期 | 标明原始日期范围和更新时间；不标作今天的新预报；不适用时显示不可用 |
| 城市无匹配 / 同名多地 | 输入下方解释和选择器；避免静默选择错误城市 |
| 行程日期无效 / 超出 30 天 | 就地提示允许范围；保留有效输入 |
| 查询中 / 超时 / 上游故障 | 提供简短加载与错误反馈，可重试；**绝不编造穿衣建议** |
| 很长的建议文案 / 系统放大字体 | 卡片随内容增高，按钮不遮挡，正文不截断 |

## 7. V1 视觉验收与后续顺序

- 在 320、375、390、430px 与普通桌面宽度检查首页、预报结果、历史参考结果以及上述主要错误状态；不能横向溢出。
- 用真实 Python 规则可能输出的**长文案**验证断行；视觉稿中的城市/温度只能标为示例，不声称当日实际天气。
- 检查正文/按钮对比度、触摸目标、焦点、表单字段标签、语义标题和屏幕阅读顺序；不用动画或图片牺牲首屏可读性。
- **下一步**：基于本规格做可实际点选的 Mobile-first 视觉原型，再对照这份规格审查；只有视觉与交互确认后才进入完整网页实现。本 PR 不写界面代码、不安装依赖、不部署、不合并。

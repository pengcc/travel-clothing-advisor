# 穿衣建议模型优化 — 小范围 Implementation Plan

基线：`pengcc/travel-clothing-advisor` 的 `main`，已合并 PR #29（merge commit `f9b17d5a5ea565bbabd5e59243c0f9f24d1c4b87`）。参考用户提供的两篇德国十一月穿衣讨论（整理于未合并的 PR #31）；本计划**不依赖 PR #31 合并**。当前 Web 是 **temperature-only**；这是改进建议表达而非重建气象/分级模型。

## 目的和完成后的用户体验

帮助用户判断外套要多厚、有什么可替代的搭配、怕冷是否需要额外下装，以及室内外如何增减。建议是**条件式备衣参考**，不是对用户现有衣物保暖能力或实际出行方式的鉴定：当前没有衣柜清单、户外停留时长等输入。避免把所有可能衣物堆成「全都要带」，并保留 PR #29 已实现的历史常见外套与偏冷风险区分。

建议输出示意（**合成场景，不是实际杜塞尔多夫天气或经验证的服装性能**）：日间代表温度在 L5、早晚偏冷，普通偏好。**主结论**：`建议带保暖夹克或轻羽绒。` **完整结果页中的条件式替代提示**：`如果已有三合一外套加抓绒，且这套衣物的实际保暖能力适合预计活动，也可替代主外套方案；不是让你再多带一套。` **内搭**：`长袖搭配毛衣或抓绒，进入较暖的室内可脱下外层。` 不能因用户看到「三合一」就推定足够保暖，也不知道其是否会长时间在户外；早晚触发的偏冷需求仍在独立提醒中。不能仅凭 3–11°C 的最高/最低范围推断确切档位。

## 具体改动

1. **保留计算，不改等级**：`experiments/clothing-rules/validate_clothing_rules.py` 的 L1–L6 边界、`web/live.py:packing()` 的代表档位/跨日触发与预报日期、13°C 容差、`web/historical_advice.py` 的五年冷暖参考、早晚提醒全部保持原有语义。不新增气象请求、缓存键、输入字段或温差等级。
2. **外套表达（优先 L4/L5/L6）**：原有短 `headline`/`OUTER` 仍是主外套结论，供首页城市卡片和冷热变化提醒复用；**替代说明只在完整结果页和复制摘要中出现，不塞进 `OUTER` 或卡片摘要**。单次最多给一个**互斥的条件式替代组合**（如 L5「如果已有且保暖合适的三合一+抓绒，可替代保暖夹克/轻羽绒」），不是新增一件必须打包的外套或抓绒；不承诺任意三合一的性能，也不判断用户是否已拥有。若跨日、早晚或历史样本已触发 L6 冬季防寒要求，不以 L5 替代组合覆盖或削弱 L6，必要时省略替代句。L6 明确冬季保暖外套/保暖内搭；L1/L2 的「不需厚外套」不能变成要额外带厚外套，L3 不建议厚外套。
3. **个人冷热偏好与层次**：保留 `normal/cold/hot` 三选项，档位与天气事件不随偏好改变。正常偏好给通常的内搭；怕冷时选择**有用且未被通常/偏冷需求覆盖**的可脱保暖层或更厚中间层；怕热时允许改薄中间层，但不能取消已触发的 L6/早晚保暖覆盖。区分「带着应对偏冷时段」和「全天必须穿」，不重列为另一件必须带的同功能衣物。不按籍贯推断体感，也不保证室内都有供暖。
4. **裤子/鞋子**：完整结果页只在实际有帮助的档位（主要 L4–L6）附**一条短提示**：普通长裤、适合步行的鞋；怕冷或较冷条件可按体感备保暖裤（L6 不能因「可选」而隐去真实偏冷覆盖）。「如另查预报提示雨雪，再考虑防水鞋；如有结冰风险注意防滑」只能是**条件句**，不能暗示温度模型预测了雨雪、结冰或测出风速。没有额外天气字段，不新增第二套裤鞋分级、必带清单或活动问卷。
5. **同步页面与复制摘要（确定数据路径）**：保留 `web/live.py`/`web/historical_advice.py` 现有主档、风险事件及 `headline/layers/notices/packing_variation_notice` 的计算。扩展 PR #29 的 `web/advice_copy.py:packing_copy(main, events, ...)`：由两种后端路径**明确传入** `preference`（旧测试调用可默认 `normal`），用**已有选定档位、split 与风险事件**生成 `packing_copy.guidance`，仅含可为空的 `alternative`、`personal_layer`、`trousers_shoes` 三个短字符串。现有 `packing_copy.outer/inner/risks` 保留，并以已有温度判断结果为依据；此处只能决定衣物表述，绝不重新推断气温或天气。完整结果页的三个额外提示从**同一份** `data.packing_copy.guidance` 展示，复制函数 `web/static/components.js:formatAdviceCopy` 读取相同值，按需写入复制文本；`web/static/app.js` 只负责展示。不允许仅在 `layers` 或 `notices` 拼接后忘记复制，也不允许 JS 另写一套服装规则。正常预设、个人冷热文案及新增裤鞋提示都应在这一个出口体现；避免原 `layers` 中的个人偏好尾句与 `guidance.personal_layer` 重复。对旧版/模拟响应缺少 `packing_copy` 时沿用现有回退行为，不伪造新建议。
6. **轻量而不过度**：首页卡片只显示原有短外套结论与 variation summary；完整结果页在主建议后按需显示**不超过三条简短提示**，复制摘要同步，不做新增清单或可折叠长文。L5 正常/怕冷/怕热与 L6 偏冷例外的备衣含义必须一致；当 `main=None` 或仅晚间可用时也不强行指定通常档位。已有来源、真实/历史模式、免责声明、移动端布局和用户表单不变。

## Codex 应如何实施

- 在 PR #29 已合并的**最新 `main`** 上创建独立实现分支；**不要**在未合并的 PR #31 证据分支上实现。
- 先确认现有主外套、内搭、个人调整、历史偏冷提醒和 `packing_copy` 的现行输出，再完成第 5 条定义的单一服务端提示来源及前端两个消费者。**不要**重写既有复制摘要的风险去重或退化为 DOM 拼接；如有更小的等价实现，可采用，但必须保证页面/复制共用同一服务端已决定的建议。
- 测试只覆盖改变的行为和已知回归风险：L5 正常/怕冷/怕热的 `guidance` 页面/复制一致；三合一是可选**替代**而非第二件必带衣服；L5 通常与历史或早晚 L6 偏冷共存时仍明确冬季外套、保暖内搭（不被替代文案抵消）；接近13°C、`main=None` 的冷热分化、L1/L2 无厚外套、只有早晚偏冷、temperature-only 不伪造风雨雪；旧模拟响应复制回退；整份复制字符串无无关重复。复用 `tests/web/` 现有夹具和回归脚本，不额外建立研究/验收体系。
- 至少运行 `python3 -m unittest discover -s tests/web -q`、`python3 -m unittest discover -s experiments/clothing-rules -q`，以及与建议/复制有关的现有浏览器回归（本地具备 Playwright/Chrome 时）；报告未运行条件及任何未验证点。
- 交付一个实现 PR，描述用户可见变化与边界；不要合并、部署、修改历史数据或扩展 API 获取范围。

## 明确排除

不重新校准 L1–L6，不加入雨/雪/风数据，不做用户衣柜管理、行李件数算法、个人体感学习、每日穿搭排程或 LLM 自由生成。PR #31 的资料仅说明为什么希望改善备衣决策，**不被当作服装保暖、德国天气或模型阈值的验证**。

# 穿衣建议模型优化 — 小范围 Implementation Plan

基线：`pengcc/travel-clothing-advisor` 的 `main`，已合并 PR #29（merge commit `f9b17d5a5ea565bbabd5e59243c0f9f24d1c4b87`）。参考用户提供的两篇德国十一月穿衣讨论（整理于未合并的 PR #31）；本计划**不依赖 PR #31 合并**。当前 Web 是 **temperature-only**；这是改进建议表达而非重建气象/分级模型。

## 目的和完成后的用户体验

回答「已有三合一+抓绒，还需再带厚羽绒吗？」「怕冷是否加秋裤？」「室内外怎么增减？」，用一条清晰的主要外套选择、必要时的等功能替代和简短的备选层说明。避免把所有可能衣物堆成「全都要带」，尤其保留已实现的历史常见外套与偏冷风险区分。

建议输出示意（**合成场景，不是实际杜塞尔多夫天气或经验证的服装性能**）：日间代表温度在 L5、早晚偏冷，普通偏好：`主要准备保暖夹克或轻羽绒；已有保暖能力适合的三合一外套加抓绒，也可作为替代。长袖搭配毛衣或抓绒，进入室内便于脱下。` 早晚触发的偏冷需求作为原有独立提醒；不能仅凭 3–11°C 的最高/最低范围推断确切档位。

## 具体改动

1. **保留计算，不改等级**：`experiments/clothing-rules/validate_clothing_rules.py` 的 L1–L6 边界、`web/live.py:packing()` 的代表档位/跨日触发与预报日期、13°C 容差、`web/historical_advice.py` 的五年冷暖参考、早晚提醒全部保持原有语义。不新增气象请求、缓存键、输入字段或温差等级。
2. **外套表达（优先 L4/L5/L6）**：让主外套决定简短明确，再**至多一个**合理替代例子；特别是 L5 可解释「合适的三合一+抓绒」可替代保暖夹克/轻羽绒，不承诺所有标为三合一的衣服保暖相同。L6 仍明确冬季保暖外套及保暖内层，不能因替代方案弱化偏冷保护。L1–L3 的“不需要厚外套”结论不得变成“多备厚外套”。
3. **个人冷热偏好与层次**：保留 `normal/cold/hot` 三选项，档位和天气事件不因个人偏好改变；调整为具体、可选的中间层决定（例如较怕冷的 L5 可备用一件可脱保暖层；怕热可以减薄中间层，但不移除必要的偏冷备衣覆盖）。不得重复列出主建议已包含的衣物，也不得假定广东/东北籍贯等于体感偏好。进出室内可增减层，不承诺每个场馆均有供暖。
4. **裤子/鞋子**：结果页仅在确有实用价值（主要为偏冷档）增加**一条简短、低优先级提示**，例如普通长裤为基础，怕冷可备用薄保暖裤；鞋优先合脚、适合步行。当前 temperature-only 输入**不能断言这趟会下雨/下雪/结冰**；可作条件式「临近预报有雨雪再考虑鞋面防水、地面结冰注意防滑」，不能写成模型检测出的风雨雪提醒。不新增第二套裤鞋分级、必带清单或用户活动问卷。
5. **同步页面与复制摘要**：以已有服务端决定为唯一事实来源。同步调整 `web/live.py`、`web/historical_advice.py` 和 PR #29 引入的 `web/advice_copy.py`，确保页面 `headline/layers/notices/packing_variation_notice` 与 `packing_copy` 没有外套替代含义冲突、错位归类或重复。前端仅做必要的展示与复制字段适配（`web/static/components.js`、`web/static/app.js`），不在 JavaScript 中做任何温度或天气推断。若新建小辅助函数，可只用于整合衣物选择文案，不引入框架/新依赖。
6. **轻量而不过度**：城市首页卡片仍保持当前紧凑的外套决定与已有的 variation summary；裤鞋建议仅放完整结果，复制摘要也应包含有用信息但不引入单独的庞大 checklist。已有来源、真实/历史状态、免责声明、移动端布局与用户表单不变。

## Codex 应如何实施

- 在 PR #29 已合并的**最新 `main`** 上创建独立实现分支；**不要**在未合并的 PR #31 证据分支上实现。
- 先确认现有主外套、内搭、个人调整、历史偏冷提醒和 `packing_copy` 的现行输出，再做以上最小更改。避免重写现有复制摘要算法或将其退化为从 DOM 拼接。
- 测试只覆盖改变的行为和已知回归风险：L5 正常/怕冷/怕热、L5 通常与历史 L6 偏冷共存、接近13°C、无主档的冷热分化、L1/L2 无厚外套、只有早晚偏冷、temperature-only 不伪造风雨雪、结果页与完整复制字符串一致。复用 `tests/web/` 现有夹具和回归脚本，不额外建立研究/验收体系。
- 至少运行 `python3 -m unittest discover -s tests/web -q`、`python3 -m unittest discover -s experiments/clothing-rules -q`，以及与建议/复制有关的现有浏览器回归（本地具备 Playwright/Chrome 时）；报告未运行条件及任何未验证点。
- 交付一个实现 PR，描述用户可见变化与边界；不要合并、部署、修改历史数据或扩展 API 获取范围。

## 明确排除

不重新校准 L1–L6，不加入雨/雪/风数据，不做用户衣柜管理、行李件数算法、个人体感学习、每日穿搭排程或 LLM 自由生成。PR #31 的资料仅说明为什么希望改善备衣决策，**不被当作服装保暖、德国天气或模型阈值的验证**。

# XHS-001 — Complete-input desk stress test (Round 2)

> 2026-10-13 · Product Discovery / Problem Validation · **合成条件演练，没有真实参与者，也没有实际天气/衣物性能验证**。这里的城市、日期范围、温度、衣物、质量、体积、穿着体验和行程都是为测试而设计的假设，**不是 XHS-001 原作者的事实，也不是给德国旅行者的真实建议**。

## 要检验的具体问题

[第一轮 XHS-001 回答对比](xhs-001-answer-comparison.md) 已表明：缺少行程、衣物能力和行李空间数据时，负责任的普通答案与风险答案都不能宣布哪件可以省。第二轮固定一个 **包含已充分覆盖能力的具体假设分支**，问：

1. 补齐关键事实后，能否给出一项具体、带条件的减法决定，而不是继续说“资料不够”？
2. 在 **完全相同的资料、建议和风险边界** 下，五字段风险型回答是否比优质普通回答提供额外的 **可审计理由**？
3. 如果假设中的覆盖边界被破坏，能否及时撤回“可省”结论？

原始用户需求只来自 [XHS-001 的证据记录](xiaohongshu-evidence.md#xhs-001--看天气是十度)：不托运行李、装不下、是否带大衣，作者后来表达大衣／羽绒背心／软壳的意向。以下 **任何具体数值都不属于原帖**。

方法依托已有 [Manual Answer Test Harness](manual-answer-test-harness.md) 的公平配对、遗漏门槛、穿/带和 adverse 检查；[Product Validation Baseline](product-validation-baseline.md) 仍未达成。本文件不修改 harness，也不把桌面推演包装为参与者试验。

## 1. 冻结的 **完全虚构输入**（synthetic fixture R2-v1）

假设是一个旅行者计划德国城市短途旅行；给 A/B **同一份已明确的假设事实**。这里的“有过穿着体验”同样是假设，没有现实中的实际测试。

| 项目 | 为此次演练**假设**的具体条件 |
| --- | --- |
| 行程 | 一座德国城市，4 天；普通步行观光和公共交通，室内可脱外套；不参加正式着装活动，没有远郊长时间静止暴露 |
| 条件范围（**不是实际天气预报**） | 设定早晚 7°C、白天约 15°C；有风；其中一段步行可能遇到最多 30 分钟小雨；本次演练的**已知范围不包含**强降雨、低于 7°C 或长时间静止户外 |
| 既有基础层 | 长袖内搭 + 抓绒衣已经在行李中，体积/重量记入已用额度；两者能和下述背心、软壳同时穿 |
| 候选大衣 C | 假设重 **1.10 kg**、折叠体积 **5.5 L**，主要提供保暖；没有被验证的可靠防雨能力；此次旅行无外观/正式着装独特需求 |
| 候选羽绒内搭背心 V | 假设重 **0.24 kg**、折叠体积 **1.0 L**，可与基础层及软壳叠穿，增加躯干部位的保暖 |
| 候选软壳 S | 假设重 **0.37 kg**、折叠体积 **1.5 L**；可挡本次假设的风；旅行者曾在同等程度小雨中使用，并认为这段时间可满足其需求；**不推断一般软壳防水** |
| 保暖/雨天覆盖前提 | **专门设定**该旅行者此前在等同于上述最冷/有风暴露的条件下，穿“基础层 + V + S”步行 45 分钟自觉足够舒适；在已设定雨段内也可接受。没有证据表明这对其他人或更恶劣条件适用 |
| 行李余量 | 仅随身行李，净剩余约 **0.65 kg** 以及 **2.5 L** 空间；其他非衣物不可挪动；不能增加托运行李。V+S 合计 **0.61 kg、2.5 L**，两项均在假设限额内；大衣单件 **1.10 kg、5.5 L**，两项均超 |
| 旅行中携带 | 另外假设小背包在外出时可提供 **4 L** 的闲置空间，足够存放脱下的 V+S（2.5 L）以及抓绒（假设折叠 1.5 L）；空间仅在本演练成立 |

**一致性核对：** V + S = 0.24 + 0.37 = **0.61 kg**；1.0 + 1.5 = **2.5 L**。与 0.65 kg / 2.5 L 净余量相比，还剩 0.04 kg 且**零体积余量**；大衣 C 超出重量 0.45 kg、体积 3.0 L。体积不可加性、实际压缩变化、航司规则和重量计量误差在现实中都可能存在；这里专为隔离决策逻辑而约定数值确定，不能当作真实装包承诺。

### 预先冻结的候选决定与证据门槛

- **在以上合成假设成立时：** 保留已经装好的基础层，带 V+S，**不把大衣 C 加进行李**。因为已明确假设 V+S 与基础层覆盖整个设定的有效暴露，C 此行程没有独有功能且装不下。这是一次 **fixture-only, conditional omission**，不是现实中“大衣可安全不带”。
- **不能偷换为：** 十度就不带大衣；所有软壳可防雨；所有羽绒背心足以御寒；上飞机穿着大衣即可解决白天收纳；旅行者真实测试了这些衣物。
- **触发撤回的条件：** 可信的额外寒冷/强雨/长时间静止户外、现有软壳性能不足、叠穿不合适、没有相当条件的实际舒适经验、必须穿大衣的活动场合、背包装不下脱下的层、行李称重/体积不满足。出现这些情况，不直接反推“一定带大衣”，而是 **重新核对覆盖与可用替代方案**。

## 2. 两种正常质量的回答（冻结 v1）

以下两个回答的**事实、最终动作、例外条件与下一步建议相同**。仅把信息组织为连续建议 vs 显式取舍框架。A 绝不是刻意劣化的“把所有衣服都带上”。

### A — 普通实用建议

> 这次假设行程是四天城市观光，早晚 7°C、白天 15°C，有风且只考虑短时小雨。你已装好长袖和抓绒，过去在同类条件下试过“这两层＋羽绒背心＋软壳”，觉得保暖和风雨应对都够用。按本次约定的范围，不需要再额外塞一件大衣；它没有特别要应付的场合，重量和体积也超出余量。
>
> 建议带背心和软壳：共 0.61 kg、2.5 L，刚好符合剩余 0.65 kg、2.5 L 的限额；大衣 1.10 kg、5.5 L 则两项都超出。早晚按需要叠穿，中午脱下的衣服放进有 4 L 余量的随身小背包；不要把“穿在身上”算成不需要收纳。这件软壳能应对小雨也只是此处对既有使用体验的假设，不代表所有软壳都防雨。若后来出现更低温、强雨、软壳不适用或活动改变，就重新检查保暖/防雨组合，不能照抄“不带大衣”。这不是通用气温规则。

### B — 风险与行李取舍导向建议

> **主要风险：** 追加一件 1.10 kg、5.5 L 的大衣会超过随身行李余量；反过来，为减重删掉唯一有效防风雨或保暖层也不行。
>
> **需要保留：** 已装好的长袖和抓绒，加上曾在同类 7°C、有风及短时小雨条件下让你舒适的羽绒背心＋软壳。本次假设中它们已覆盖既定暴露。
>
> **可以省略：** 在**这四天假设行程**中，不再额外带大衣：它没有独有的活动或防护用途，且装不下。背心＋软壳合计 0.61 kg、2.5 L，恰好符合余量；这不代表真实天气下安全省略。
>
> **穿与带：** 早晚叠穿，白天拆下的层放 4 L 余量的小背包，不把出发穿衣等同于免收纳。
>
> **信心边界：** 一旦实际出现更冷、强雨、软壳能力不足或行程改变，撤回省略判断并重新核对组合；不能直接套用到真实出行。

## 3. 等价性检查与桌面结果

| 维度 | A | B | 判定 |

| 结构区别 | 连贯叙述 | 风险/保留/省略/携带/边界分栏 | B 可扫描，但没有证据证明更易执行 |

**桌面结果：** 本次构造的“完整证据”确实让两份合理回答都可以给出 **条件性的减法结论**（仅在 fixture 内不额外带 C）。然而 **B 并没有在相同事实下提供 A 无法提供的取舍动作或保留能力**。两者在这个受控单例的功能性结果相同；不能由此认定真实用户偏好、阅读效率或正确执行也相同，更不能声称产品价值已被验证。

## 4. 最小反例：如果边界变了，必须怎么处理

这些不是新的真实帖子，也不是额外仿真天气资料。仅对固定案例做局部反事实检查，避免“假设完整”让结果看上去永久正确。

| 仅改变的假设 | 影响 | A 和 B 都必须怎样响应 |
| --- | --- | --- |
| 软壳不再能覆盖预计的 30 分钟小雨，且没有其他可靠保护 | 防雨能力出现缺口 | 撤回“当前组合充分覆盖”的依据；不能凭大衣类别推定它防雨，也不能无理由保留或丢弃 C |
| 一晚温度低于此前体验过的下界，且需久站户外 | 原来的个人舒适经验证据不覆盖新增暴露 | 重新确认保暖层及可替代方案；不能把原省略作为全程安全承诺 |
| 新增必须穿大衣的正式场合（且没有可替代/借用的服装） | C 可能有独有用途，但它仍不符合原行李额 | 改变行李/着装方案，说明约束冲突；不能同时保证 C 必须带又保证原 0.65 kg / 2.5 L 限制满足 |
| 小背包不再有能放脱下层的空间 | 早晚穿/白天带的计划不可执行 | 修正当天穿/带计划或寻找其他可行收纳，不能把“穿上飞机”当成零负担 |

**安全门槛：** 本案“可省 C”的逻辑依赖假设的保暖/风雨覆盖、个人适应、整体行程、体积和收纳空间一起成立。少掉任何物质性证据，都只能撤回肯定的“安全省略”，改为明确的条件性未决状态；这不是推荐一定回头带 C。

## 5. 结论及下一次真正有信息量的验证

- **事实层：** XHS-001 原作者明确有不能托运和装不下的取舍问题，但仍不知道其最后带什么、用得如何。本轮无新增原帖事实。
- **推演层：** 在人为设定的完整条件下，两种成熟回答 **都能** 用同一组理由帮助完成一个逻辑上的减法；五字段结构未展现额外的 *客观决定内容*。这只是文本与决策逻辑的桌面审核，不是“用户已被帮助”的观察。
- **关键区分：** 一种可能的产品价值不在答案外观，而在**以低负担拿到真正改变决定的资料、处理衣物能力替代，并解释何时不能安全省略**。这是值得进一步检验的假设，不是通过本次演练建立的差异化能力。
- **停止无增量循环：** 不再为了获得“显著优于普通答案”的漂亮结论，反复修改 A/B 文字或构造更多容易获胜的假设。也不把下一步自动升级为实现系统。
- **最小有区分度的后续工作：** 使用现有 PR #5 方法，在一次**真实的具体行李取舍**中记录基线选择、常规合格建议与风险型建议所导致的选择/理解（普通建议同样可胜出）；如果暂时没有这样的场景，就转而评估**资料获取负担**以及当前天气/打包工具是否已能解决同类决定，不虚构参与者数据。

**验证状态：** PR #5 参与者测试仍未执行；Product Validation Baseline 尚未满足；本轮没有新天气源、应用代码、测试工具或产品架构决策。
